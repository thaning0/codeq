# codeq 0.5.1 Quant performance baseline

Repository: `/home/thn/Quant`

Method: `benchmarks/quant_benchmark.py`, 2 measured runs per query. `cold` creates and closes a fresh `Workspace` for each run; `warm` first runs the representative workload once, then reuses the same `Workspace`. RSS is the sum of resident memory reported by live LSP child processes, not Python/codeq RSS.

| Query | Cold P50 ms | Cold P95 ms | Warm P50 ms | Warm P95 ms |

## Acceptance

- Warm semantic `context`/`trace` queries are comfortably below the 1 s P50 target and below 3 s P95.
- Cold Python semantic context/trace stays below 4 s in this run; there are no 10 s+ semantic outliers.
- Warm exact symbol context shows document-symbol cache hits with zero document-symbol misses after warm-up.
- The cache is bounded to 256 document entries per Workspace and invalidates on `(mtime_ns, size)` changes.
- Adaptive prewarm only stops early after the current result budget is satisfied; it never infers completeness merely because two probes were stable.
- A fully warmed representative Workspace reached roughly 1.35 GB combined LSP RSS. This is dominated by basedpyright/typescript-language-server processes; existing workspace idle eviction remains the memory-pressure boundary.

## Telemetry contract

JSON `_meta` now includes per-request deltas:

```text
lsp_started
lsp_request_count
prewarm_files
prewarm_probes
prewarm_early_stops
cache.document_symbols_hit
cache.document_symbols_miss
cache.document_symbols_evicted
cache.document_symbol_entries
```

Text/lexical queries additionally report matching-file and tracked/untracked matching-line counts in `_meta.text`.

The full machine-readable samples are in `benchmarks/results/0.5.1-quant.json`.
