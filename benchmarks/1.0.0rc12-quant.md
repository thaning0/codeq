## Focused FTS5 probe

A separate run used five representative multi-token queries, 50 warm searches,
and ten complete contentless rebuilds:

- 2,584 Git-visible supported source files and 25,696,128 source bytes;
- 6,660,096 index bytes, or 25.92% of source bytes;
- first public `find`: 267.5 ms, including a 177.3 ms index build;
- rebuilds: 158.9-196.0 ms, median 181.5 ms;
- warm public `find`: 78.3 ms median, 97.9 ms P95, including freshness checks;
- FTS SQL: 0.726 ms median, 1.457 ms P95;
- process RSS delta after first build: 15,360 KiB;
- zero LSP requests and zero language-server sessions.

The corpus has 11 more files than the feasibility probe because the production
implementation indexes every supported extension, including `.mjs` and `.cjs`.
Build time remains inside the earlier 171.9-193.9 ms median range aside from normal
run variance. The index is 0.36 MiB larger and process RSS is about 3.3 MiB higher;
that includes path/filter metadata, ranked rows needed for exact filtered counts,
and Python/SQLite allocator overhead. It adds no installed dependency or persistent
state. The broader five-query sample sometimes returns most of the corpus to compute
post-filter totals, explaining the roughly 1 ms SQL P95 increase; this is immaterial
relative to the sub-100 ms warm public query.

The full machine-readable samples are in
[`results/1.0.0rc12-quant.json`](results/1.0.0rc12-quant.json). The RC12 readiness
gate passes all ten correctness/performance checks.
